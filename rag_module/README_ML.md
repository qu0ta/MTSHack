# ML-часть: RAG-консультант МТС EnergyTool

Отвечает на вопросы клиента по базе знаний EnergyTool и ведёт диалог как консультант: прямой ответ, ключевые факты из базы, один уточняющий вопрос. Один и тот же код работает в двух режимах: автоматическая проверка на платформе (`solution.py`) и сайт (`rag_api.py`).

## Как устроена цепочка

1. **Индекс.** Документы базы режутся по заголовкам Markdown на фрагменты до 1100 символов; к каждому добавляются имя файла и путь заголовков.
2. **Поиск.** BM25 с простым русским стеммингом и семантический поиск по эмбеддингам `BAAI/bge-m3` объединяются через RRF; 12 лучших кандидатов переупорядочивает `Qwen3 Reranker 8B`, остается 5.
3. **Контекст.** К фрагментам добавляются полные тексты одного-двух главных документов (если второй тоже явно лидирует), разделы «Чего утверждать нельзя» и «Что мы не делаем» найденных продуктов и список «что уточнить у клиента» из справочного документа по расчету.
4. **Примеры.** Из 18 эталонных пар подбираются 8 самых похожих по смыслу (эмбеддинги, запасной вариант BM25); они задают стиль, длину и логику ответа.
5. **Генерация.** Единая модель `Qwen3.8-27B`, температура не выше 0.2, ответ 30–60 слов.

Диалог: поиск строится по репликам клиента с учетом последнего вопроса консультанта; для сайта в промпт идут последние 12 сообщений, в поиск последние 6.

## Режимы

| | Конкурсный (`solution.py`) | Сайт (`rag_api.py`) |
|---|---|---|
| Вход | `questions.csv` | `generate_answer(query, history)` |
| Выход | `submission.csv` | `{answer, sources, documents, degraded, timings_ms}` |
| Сбой API | подставляется вежливая фраза про специалиста | исключение (`generation_failed (...)`) |
| Заявка | подсказка в промпте | модель не утверждает, что заявка создана; сохраняет сайт |
| Время | лимит платформы 20 минут | бюджет `RAG_BUDGET_SECONDS` на один запрос |

## Контракт `rag_api.py`

Функции синхронные и потокобезопасные после `init()`. `history` содержит реплики до текущей, без текущей. Если первой идёт реплика, начинающаяся с «Параметры объекта» или «Справочные параметры», она всегда сохраняется.

- `init(kb_path=None, site_mode=True)`: один раз при старте, строит индекс; `health()` возвращает `{"ready", "degraded"}`.
- `search(query, history=None, top_k=5)`: список `{source, title, text, score}`; `score` ранговый, не вероятность.
- `build_context(query, history=None)`: всё, что подаётся в модель (фрагменты, документы, ограничения, вопросы для уточнения, примеры).
- `generate_answer(query, history=None)`: полная цепочка, возвращает `answer`, `sources`, `documents`, `degraded`, `timings_ms`.

`degraded` перечисляет деградации: `embeddings_unavailable`, `query_embedding_failed`, `reranker_failed`, `example_embeddings_unavailable`, `example_embedding_failed`.

`solution.py` и `rag_api.py` обновляются только вместе: при несовпадении `VERSION` импорт `rag_api` завершается ошибкой.

## Переменные окружения

Шаблон: `ml.env.example`. Ключи не хранятся в репозитории. `LLM_BASE_URL` общий для генерации, эмбеддингов и реранкера; ключи можно разделить через `EMBEDDER_API_KEY` и `RERANKER_API_KEY`. Платформа организаторов подставляет все значения сама.

## Проверки

```
KB_PATH=<путь к базе> python test_ml.py     # 9 проверок на локальном API, без ключей
python site_check.py                         # смоук-тест на настоящем API (около 8 запросов)
python make_submission.py . submission.zip   # сборка и проверка архива для платформы
```

`make_submission.py` проверяет состав архива (только `solution.py` и `requirements.txt` в корне), точные версии зависимостей из разрешенного набора, отсутствие ключей, `pip install` и запуска процессов.

## Результаты и методика

Автоматическая оценка на публичной выборке платформы. Повторные запуски одной и той же версии показали разброс около ±0.04 (0.608, 0.557, 0.632), поэтому различия меньше примерно 0.05 мы не считаем значимыми.

| Шаг | Счёт |
|---|---|
| Исходный вариант: чанки по 450 символов, 3 фрагмента, общий промпт | 0.430 |
| Короткие ответы в стиле эталона, ответ не обрывается | 0.490 |
| Ограничения продукта и список «что уточнить» из базы | 0.502 |
| Полные тексты главных документов в контексте | 0.512 |
| Длинные ответы (80–130 слов) | 0.507 |
| Второй проход проверки ответа | 0.542 |
| Включены размышления модели | 0.581 |
| Подбор 5 похожих эталонных примеров и правило заявки | 0.577 |
| То же, 8 примеров (три запуска одной версии) | 0.608 / 0.557 / 0.632 |
| 18 примеров; примеры как реплики чата; плюс FAQ-пары (два запуска) | 0.573; 0.584; 0.550 / 0.585 |

Значимой оказалась только добавка эталонных примеров (в среднем около +0.09); остальные правки в пределах шума. Итоговая версия выбрана как самая простая из эквивалентных.

## Ограничения

- Качество зависит от доступности API эмбеддингов и реранкера; без них поиск продолжает работать только по BM25 с пометкой `degraded`.
- Контекст 10–25 тыс. символов на вопрос, время ответа определяется длиной генерации.
- Эталонные примеры из демо-набора вшиты в `solution.py`. Это данные кейса: репозиторий должен быть закрытым, доступ открыт аккаунту жюри.
- Модель может ошибаться даже при правильном поиске; факты вне базы запрещены промптом, но это не гарантия.
- Реальные ответы Qwen3.8-27B вне платформы мы не наблюдали, локально проверялись другие модели.
