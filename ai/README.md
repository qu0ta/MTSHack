- `main.py` — создание приложения и подключение маршрутов.
- `api/routes.py` — HTTP endpoints.
- `schemas/chat.py` — Pydantic-модели запросов и ответов.
- `core/orchestrator.py` — временная заглушка подготовки ответа.
- `tests/test_api.py` — автоматические проверки API.

Дополнительно реализованы отдельные компоненты:

- `core/llm_client.py` — асинхронный OpenAI-совместимый клиент:
  чтение настроек из окружения, запрос генерации и обработка ошибок.
- `core/prompt_builder.py` — системные правила и сборка сообщений
  из данных клиента, фрагментов базы знаний и истории.
- `core/dialog_manager.py` — подготовка поискового запроса
  из текущей и последней предыдущей реплики клиента.

Эти компоненты пока не подключены к HTTP-сценарию.
POST /api/v1/chat продолжает возвращать фиксированный ответ stub.

Клиент LLM проверен с подменёнными HTTP-ответами.

## Установка зависимостей

Выполняйте команды из папки `ai/`. Требуется Python 3.11+.

Создайте виртуальное окружение при первой установке:

```bash
python3 -m venv .venv
```

Активируйте его и установите зависимости:

```bash
source .venv/bin/activate
python -m pip install -r requirements.txt
```

Зависимости устанавливаются в локальное окружение `.venv`.
При открытии нового терминала окружение нужно активировать снова.

## Запуск сервера

Из папки `ai/` с активированным окружением:

```bash
python -m uvicorn app.main:app --reload
```

- Проверка сервиса: http://127.0.0.1:8000/health
- Интерактивная документация: http://127.0.0.1:8000/docs

Для остановки сервера нажмите Ctrl+C в терминале.


## Настройки окружения

`.env.example` содержит образец переменных для будущего подключения LLM:
`LLM_BASE_URL`, `LLM_API_KEY`, `LLM_MODEL`.

Текущий stub не использует эти переменные.
Автоматическая загрузка `.env` пока не реализована.
Файлы `.env` и папка `.venv` исключены из Git через `.gitignore`.

## Запуск тестов

Из папки `ai/` с активированным виртуальным окружением:

```bash
python -m pytest -q
```

Запускать Uvicorn для тестов не требуется:
TestClient обращается непосредственно к приложению.

Реализованы пять проверок:

1. GET /health возвращает HTTP 200 и статус ok.
2. POST /api/v1/chat возвращает тестовый ответ и время обработки.
3. Запрос без обязательного поля message возвращает HTTP 422.
4. Переданные данные клиента возвращаются без изменений.
5. В тестовом режиме заявка отсутствует: lead равен null.

Дополнительные тесты проверяют:

- отсутствие обязательных настроек LLM;
- успешный ответ LLM, ошибку HTTP и пустой текст;
- неожиданные структуры ответа API;
- сборку промпта и порядок сообщений;
- подготовку поискового запроса с историей и без неё.

На текущем этапе успешно проходят 15 тестов.
Тесты не требуют API-ключей и сетевых запросов.
