# MTS EnergyTool — Python AI-сервис

Сервис принимает запросы Go, передаёт текущую реплику и историю в синхронный
`rag_api.generate_answer()` ML-инженера и возвращает ответ и источники.
Второго вызова LLM для переформулирования нет. PostgreSQL и сохранение заявок — в Go.

## Структура

- `app/main.py` — FastAPI, инициализация ML при запуске.
- `app/api/routes.py` — `/health`, `/ready`, `/api/v1/chat`, HTTP-ошибки.
- `app/core/settings.py` — переменные окружения и импорт ML после их загрузки.
- `app/core/orchestrator.py` — консультация либо подготовка заявки.
- `app/core/dialog_manager.py` — история и параметры объекта из карточки клиента.
- `app/services/rag_adapter.py` — `asyncio.to_thread`, проверка результата, лимит одновременных вызовов.
- `app/services/lead_service.py` — заявка из готовых полей, без извлечения контактов и записи в БД.
- `app/schemas/chat.py` — входные и выходные Pydantic-модели.
- `app/ml/` — неизменённые `solution.py` и `rag_api.py` ML-инженера; нужны вместе.
- `tests/` — актуальные тесты сервиса без внешних API.
- `scripts/probe_models.py` — проверка доступности трёх API короткими запросами.
- `scripts/check_service.py` — реальные примеры приёмки через FastAPI, отчёты в `dist/`.

## Установка и запуск

Из `ai/`, Python 3.11+:

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
cp .env.example .env
```

Заполнить `.env`: API должен предоставлять генерацию, эмбеддинги и реранкер.
Одного доступа к бесплатной генерации OpenRouter недостаточно для подтверждения
работы полного ML-пайплайна. Базу знаний получить из приватных материалов, указать
`KB_PATH`. База и ключи в Git не добавляются. Реальные имена моделей взять у поставщика API.
Если `EMB_MODEL`/`RERANKER_MODEL` отсутствуют, используются имена из ML-пакета:
`baai/bge-m3` и `qwen/qwen3-reranker-8b`. Это не гарантия их доступности у провайдера.

```bash
.venv/bin/python -m uvicorn app.main:app --env-file .env --host 0.0.0.0 --port 8000
```

Окружение загружается до импорта ML. `init(kb_path=...)` вызывается один раз на процесс
при старте. Индекс не разделяется между процессами; для прототипа использовать один
Uvicorn worker. При отсутствии настроек/базы запуск завершается ошибкой, без скрытого stub.

## Подготовка заявки

Go передаёт `lead_requested: true` только после подтверждения пользователем.
ФИО, телефон и компания берутся исключительно из `client_data`. Если что-то отсутствует,
возвращается `lead: null` и перечень недостающих полей. Если всё заполнено — объект Lead.
`summary` — краткая выдержка: выбранная реплика о задаче клиента (до 400 символов),
параметры объекта из карточки и следующий шаг для менеджера. Реплики о контактах и
согласии не должны вытеснять ранее сформулированную задачу. Отбор выполняется правилами,
без LLM; сложные переформулировки могут быть пропущены. Если задача не найдена, это
прямо указывается. Рекомендации ассистента не выдаются за факты о клиенте.
Наличие контактов само по себе не создаёт заявку.

Python ничего не сохраняет, не отправляет менеджеру и не гарантирует идемпотентность
записи: Go должен обеспечить одну заявку на чат и сообщить пользователю результат сохранения.
ФИО/компания ограничены 255 символами, телефон — 30, как в Go. Доступность номера не проверяется.

## Ограничения интеграции

- HTTP-ожидание ограничено 55 секундами. `asyncio.to_thread` не может остановить
  синхронную функцию: после 504 она может продолжаться. Её место остаётся занятым,
  максимум — `AI_MAX_CONCURRENCY` (по умолчанию 2), сверх лимита 503. Длительно
  зависшие потоки требуют перезапуска процесса; принудительного завершения RAG нет.
- В новой паре ML `init()` включает режим сайта: сбой генерации выбрасывает исключение,
  которое становится 503. Неправильный контракт ответа — 502; истечение ожидания Python — 504.
  Отсутствие информации в базе — нормальный ответ HTTP 200.
- ML учитывает общий `RAG_BUDGET_SECONDS=45` при сетевых вызовах и паузах; настройка
  должна быть меньше внешнего бюджета Python 55 секунд. Это не принудительное завершение
  потока. Инициализация индекса в 45 секунд не входит; в присланном init режим сайта
  включается после построения индекса, поэтому стартовые вызовы используют старые тайм-ауты.
- Режим сайта запрещает модели обещать отправку заявки. Это правило промпта, не
  математическая гарантия всех ответов. Подтверждение записи всё равно делает Go.
- Недоступность embeddings/rerank допускает BM25 и отражается в `degraded` ответа.
  `/ready` показывает готовность индекса и его стартовые признаки деградации; он не
  проверяет доступность генерации/реранкера новым запросом. HTTP 200 с `status=degraded`
  означает возможность работать в упрощённом режиме, а не исправность всех API.
- `client_data` обновляет и хранит бэкенд. Python сохраняет переданные значения;
  свободный текст не превращается автоматически в поля БД.
- При изменении параметров объекта Go должен передать актуальную карточку.
  Бизнес-поля добавляются первой справочной репликой; текущий вопрос идёт отдельно.
  Структурированные ФИО/телефон/компания в LLM дополнительно не передаются.
  Контакты, уже написанные пользователем в истории, остаются частью истории.

## ML-версия и Git

Локальная пара `app/ml/solution.py` + `rag_api.py` заменена на присланную ML-инженером
версию `2026-11-13-site1`, без редактирования файлов. Полные SHA-256 — в
`app/ml/version.json`. Конкурсный промпт сравнен с прошлой версией: совпадает.
При объединении команды можно задать другой импорт
через `ML_MODULE`, сохранив `init(kb_path=...)` и `generate_answer(query, history)`.

Эксперимент с отдельным LLM-клиентом, промптом и ZIP-сабмитом перенесён в
`.local_experiments/combined-20261113/` и исключён из Git вместе с `dist/`.
Старые тесты сохранены там и не собираются обычным pytest. Поэтому число тестов
актуального сервиса отличается от прежних 32. Файлы были сохранены с проверкой SHA-256.
Текущая ветка больше не содержит отдельного генератора для рейтинга.
Это не удаляет уже существовавшие файлы из истории прошлых коммитов.

## Реальная проверка 13 ноября

На локальном OpenRouter (`LLM_MODEL=openrouter/free`) генерация доступна. Запросы к
указанным BAAI embeddings и Qwen reranker получили HTTP 403. Нельзя считать это полной
цепочкой ML. Проверены реальные консультации в режиме BM25 + LLM: рекомендация по
мощности 900 кВт, уточнение мощности по сообщению о потреблении, признание отсутствия
сведений об ERP и направление к специалистам. Время этих ответов — около 8–9 секунд.
Отдельный вопрос о точной цене без исходных данных занял около 18 секунд.
Модель free-router может меняться; балл Qwen/лидерборда по этим ответам не прогнозируется.

После выдачи рабочего доступа к embeddings/reranker повторить `scripts.probe_models`
и `scripts.check_service`: для полной цепочки ожидается `degraded: []`.

## Интеграция с актуальным Compose команды

Использовать `compose.integration.yaml` поверх корневого Compose общего проекта.
Порядок запуска, пути к env/KB и проверенные коммиты: [TEAM_SYNC.md](TEAM_SYNC.md).
Имя сервиса для Go — `ml-service`, а не `ai`. Docker daemon при сверке не был запущен,
поэтому сборка контейнеров и сквозной запуск ещё требуют проверки.
Пустые строки полей ClientData принимаются как незаполненные значения (null).
