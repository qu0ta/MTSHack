## Существенное ограничение — деградация поиска

На текущем адресе и ключе OpenRouter:

- `/chat/completions`, модель `openrouter/free`: HTTP 200;
- `/embeddings`, модель `baai/bge-m3`: HTTP 403;
- `/rerank`, модель `qwen/qwen3-reranker-8b`: HTTP 403.

Причину 403 (доступ, маршрут, модель или ограничения провайдера) по одному коду
установить нельзя. Утверждение, что все три модели доступны с текущим ключом, не подтвердилось.
В ответах присутствуют `embeddings_unavailable`, `example_embeddings_unavailable`,
`reranker_failed`. Поиск выполняется через BM25. Это не полный режим конкурсного ML.
Free-router может выбирать разные генеративные модели; эти результаты не сравниваются
напрямую с Qwen на платформе.

## Заявка

При `lead_requested=true` и полных контактах возвращается Lead. Резюме короткое:
задача со слов клиента, параметры объекта, следующий шаг для менеджера. Контактный
обмен не должен вытеснять задачу. Резюме формируется правилами без дополнительной LLM;
сложные формулировки могут потребовать уточнения. Ответ не утверждает сохранение в БД.
Контакты не извлекаются из переписки: они приходят из backend client_data.

Пример:

> Запрос клиента: «Нужно наладить учёт электроэнергии на складе.»
> Данные из карточки: регион: Москва.
> Следующий шаг: связаться с клиентом по указанному телефону и уточнить решение задачи.

## Повторить

Из ai/:

```bash
.venv/bin/python -m pytest -q
.venv/bin/python -m scripts.probe_models
.venv/bin/python -m scripts.check_service
```

Две последние команды обращаются к реальному API по локальному .env; ключи не печатаются.
Они не отправляют сабмит и не расходуют попытки лидерборда.
Запуск сервера: `.venv/bin/python -m uvicorn app.main:app --env-file .env --host 0.0.0.0 --port 8000`.
